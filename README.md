# Stormshield SNS Firewall Rule Analyzer

This script analyzes Stormshield SNS firewall rules exported as CSV files to detect common inconsistencies such as shadowed rules, duplicates, conflicts, and overlaps. It is designed to work without Stormshield Management Center (SMC) and uses only the Python standard library.

The analysis identifies the following categories of anomalies:
- **Shadowed Rules:** A rule whose matching criteria are a complete subset of a preceding rule's criteria.
- **Duplicates:** A rule that is identical to a preceding rule in terms of matching criteria and action.
- **Conflicts:** A rule that overlaps with a preceding rule but has a different action (e.g., `allow` vs. `deny`).
- **Partial Overlaps:** A rule that overlaps with a preceding rule with the same action, but is not a full subset.

## Usage

```bash
python3 detect_stormshield_anomalies.py --rules rules.csv --objects objects.csv --out report.json --md report.md
```

## Input File Formats

The script requires input files in a specific CSV format.

### `rules.csv` (Required)
- **Separator:** `;`
- **Encoding:** UTF-8
- **Headers:** The script expects the following headers.
  - `rule_id`: A unique identifier for the rule.
  - `position`: The rule's evaluation order (integer, lower is higher priority).
  - `slot`: The ruleset slot, typically `filter` or `nat`.
  - `enabled`: `true` or `false`.
  - `action`: The rule's action (e.g., `allow`, `deny`, `snat`).
  - `src`: Source IPs/objects, comma-separated.
  - `dst`: Destination IPs/objects, comma-separated.
  - `svc`: Services/ports, comma-separated.
  - `proto`: Protocol, comma-separated (e.g., `tcp`, `udp`, `any`).

### `objects.csv` (Optional)
- **Separator:** `;`
- **Encoding:** UTF-8
- **Headers:**
  - `name`: The name of the object.
  - `type`: The object type (`host`, `network`, `range`, `group`, `service`, `service_group`).
  - `value`: The object's value (e.g., CIDR, IP range, list of members).

## Command-Line Options

- `--rules <path>`: **(Required)** Path to the rules CSV file.
- `--objects <path>`: Path to the objects CSV file.
- `--out <path>`: **(Required)** Path to write the output JSON report.
- `--md <path>`: Path to write a human-readable Markdown report.
- `--slot <filter|nat|both>`: The rule slot to analyze (default: `both`).
- `--ipv6 <on|off>`: Enable or disable IPv6 processing (default: `off`).
- `--unknown <fail|warn>`: Action to take if unknown objects are found. `fail` exits with an error, `warn` continues (default: `warn`).

## Known Issues & Limitations

- **Complexity:** The core analysis is `O(n^2)` in the number of rules per slot. Performance may degrade on very large rule sets (>10,000 rules).
- **Shadowing Definition:** The script defines "shadowing" as a rule being a subset of a *preceding* rule (one with a lower `position` number). This is the standard definition and matches the functional requirements provided. Some firewall interfaces may use the term differently.
- **NAT Analysis:** NAT analysis is limited to the pre-translation matching criteria (`src`, `dst`, `svc`). The logic of the NAT translation itself is not analyzed.
